# lint_wiki — 위키 파일 양식 점검 및 보완

`/lint_wiki <경로>` 로 호출된다. 인자는 파일 경로 또는 디렉터리 경로다.

- **디렉터리**가 오면 해당 디렉터리 안의 모든 `.md` 파일에 대해 린트를 수행한다.
- **파일**이 오면 그 파일 하나만 린트한다.
- 경로는 볼트 루트 기준 상대 경로로 해석한다. `wiki/voca`, `wiki/voca/袖.md`, `wiki/expression` 등 모두 허용.

전체 스키마·양식의 근거는 볼트 루트의 **CLAUDE.md**와 **`templates/voca.md`** · **`templates/expression.md`**다.

---

## 핵심 원칙 (절대 규칙)

1. **기존에 이미 작성된 데이터는 절대 수정하지 않는다.** 뜻·요미가나·한자·예문·링크·태그 등 이미 채워진 값은 건드리지 않는다.
2. **빈 곳(비어 있거나 아예 없는 섹션)만 보완한다.**
3. `last_seen`·`복습횟수` 두 프론트매터 필드는 린트 대상이 아니다 — 사용자가 Meta Bind 버튼으로 관리하는 필드이므로 건드리지 않는다.
4. `raw/` 파일은 린트 대상이 아니다. 경로에 `raw/`가 포함되면 거부한다.

---

## 파일 유형 판별

파일이 **voca**인지 **expression**인지는 다음 순서로 판별한다:
1. 경로에 `wiki/voca/`가 포함되면 → **voca**
2. 경로에 `wiki/expression/`가 포함되면 → **expression**
3. 프론트매터 `type: voca`가 있으면 → **voca**
4. 판별 불가 시 → 해당 파일을 스킵하고 보고에 명시한다.

## voca 파일 점검 항목

`templates/voca.md`를 기준으로 아래 항목을 순서대로 점검한다.

### 프론트매터

| 필드 | 점검 기준 | 보완 방법 |
|------|----------|----------|
| `type` | `voca`인지 확인 | 없거나 다르면 `voca`로 추가 (단, 기존 값이 있으면 수정 안 함) |
| `품사` | 값이 있는지 | 없으면 표제어·본문에서 추론해 채운다 |
| `jlpt` | 값이 있는지 | 없으면 추론해 채운다. 불확실하면 `미상` |
| `기록일자` | 값이 있는지 | 없으면 오늘 날짜로 채운다 |
| `aliases` | 후리가나가 있는지 | 비어 있으면 요미가나를 넣는다 |
| `tags` | 주제 태그가 최소 1개 있는지 | 없으면 표제어·뜻·상위개념을 보고 적절한 주제 태그를 추가한다 |

### 본문 섹션

**제목 (`# 표제어 (요미가나)`)**
- 형식이 맞는지 확인한다. 비어 있거나 요미가나 병기가 없으면 채운다.

**`**뜻**:`**
- 비어 있으면 채운다. 이미 있으면 건드리지 않는다.

**`## 요미가나`**
- 한자가 포함된 표제어인 경우 값이 있어야 한다. 비어 있으면 채운다.
- 히라가나 표제어는 이 섹션이 없어도 무방하다.

**`## 한자`**
- 한자가 포함된 표제어인 경우 점검한다.
  - 없으면 섹션을 새로 추가하고 `한자 — 뜻`·`한국 한자` 형식으로 채운다.
  - 있지만 `한국 한자:` 줄이 없으면 그 줄만 추가한다.
- 히라가나 표제어는 이 섹션 없어도 무방 (단, 섹션이 이미 있으면 건드리지 않는다).

**`## 예문`**
- 예문이 3개 미만이면 **N2 수준 뉴스체 예문**으로 채워 3개를 맞춘다.
  - 이미 있는 예문은 절대 수정하지 않는다.
  - 추가하는 예문 난이도 기준: 뉴스·기사체, 배경·수치·구체 상황이 담긴 한 문장, JLPT N2 어휘·문형 허용.
  - 추가한 예문에 표제어보다 어려운 단어가 포함되면 아래 `## 포함 단어 풀이`에 반드시 추가한다.
- `1.  — ` 처럼 일본어와 번역이 모두 빈 줄은 "비어 있음"으로 간주한다.

**`## 포함 단어 풀이`**
- 예문 안에 **표제어보다 어려운 단어** (기준: 표제어의 JLPT 레벨보다 상위 레벨, 또는 JLPT 미등재 전문어)가 있는데 이 섹션이 없거나 해당 단어가 누락돼 있으면 추가한다.
- 형식: `단어（요미） — 뜻 (JLPT 레벨)`
- 이미 작성된 항목은 수정하지 않는다.
- 추가할 단어가 없고 섹션이 없으면 섹션을 만들지 않는다.

**`## 상위개념`**
- 비어 있거나(`[[]]` 형태) 섹션 자체가 없으면 적절한 상위개념 `[[링크]]`를 채운다.
- 이미 있으면 건드리지 않는다.

**`## 주제`**
- `#태그` 형식의 태그가 없으면 추가한다.
- 이미 있으면 건드리지 않는다.

**`## 관련어`**
- 섹션이 없으면 추가한다 (동의어·반의어 항목을 `—`로 채움).
- 이미 있으면 건드리지 않는다.

**Meta Bind 복습완료 버튼 블록**
- 파일 맨 끝에 아래 블록이 있는지 확인한다. 없으면 추가한다.
- 이미 있으면 절대 건드리지 않는다.

```
```meta-bind-button
label: ✅ 복습완료 (오늘로)
style: primary
actions:
  - type: updateMetadata
    bindTarget: last_seen
    evaluate: true
    value: "moment().format('YYYY-MM-DD')"
  - type: updateMetadata
    bindTarget: 복습횟수
    evaluate: true
    value: "(x ?? 0) + 1"
```
마지막 복습: `VIEW[{last_seen}]` · 복습 `VIEW[{복습횟수}]`회
```

## expression 파일 점검 항목

`templates/expression.md`를 기준으로 아래 항목을 순서대로 점검한다.

### 프론트매터

| 필드 | 점검 기준 | 보완 방법 |
|------|----------|----------|
| `기록일자` | 값이 있는지 | 없으면 오늘 날짜로 채운다 |
| `tags` | 출처 태그가 있어야 한다는 강제 규칙은 없다. 값이 있으면 건드리지 않는다 | — |

### 본문 섹션

**제목 + 후리가나 (`# 관용어 (후리가나)`)**
- 형식이 맞는지 확인한다. 후리가나 병기가 없으면 채운다.

**설명 (3~4줄)**
- 제목 바로 아래 의미·유래·뉘앙스 설명이 있는지 확인한다. 없으면 3~4줄로 작성한다.
- 이미 있으면 건드리지 않는다.

**`## 후리가나`**
- 관용어 전체 읽기가 있는지 확인한다. 없으면 채운다.

**`## 예문`**
- 예문이 3개 미만이면 N2 수준으로 채워 3개를 맞춘다. 이미 있는 예문은 수정하지 않는다.

**`## 포함 단어 풀이`**
- 관용어 안에 JLPT N3 이상 난이도 단어가 있는데 섹션이 없거나 해당 단어가 누락되면 추가한다.
- 해당 단어가 `wiki/voca/`에 있으면 `[[링크]]`로 연결한다.
- 이미 작성된 항목은 수정하지 않는다.

**Meta Bind 복습완료 버튼 블록**
- voca와 동일하게 파일 맨 끝에 있는지 확인하고, 없으면 추가한다.

---

## 절차

1. **경로를 파싱한다.** 디렉터리면 `*.md` 파일 목록을 구성하고, 파일이면 그 파일 하나를 대상으로 한다.
2. **파일별로 순서대로 읽고 위 점검 항목을 체크한다.**
3. **보완이 필요한 항목만 Edit으로 추가한다.** 기존 내용 블록은 건드리지 않는다.
4. **처리 중 예문을 새로 작성할 때** 해당 섹션의 비어 있는 번호(예: `2.  — `, `3.  — `)를 찾아 그 자리를 채우거나, 번호가 아예 없으면 새 줄을 추가한다.
5. **모든 파일 처리 후 관리자에게 요약 보고한다.**

### 처리된 파일 수: N

  - 예문 2번·3번 추가
  - 포함 단어 풀이 추가 (障害, 遅延)
  - 복습완료 버튼 블록 추가
  ...

### 변경 없음 (이미 완전함)
- 파일명1
- 파일명2

### 스킵됨 (유형 판별 불가 또는 raw/)
- 파일명
```

**기존 데이터를 단 한 글자도 수정하지 않는 것이 핵심이다.**
