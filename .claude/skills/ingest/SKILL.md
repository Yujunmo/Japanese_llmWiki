# Ingest — raw 파일을 위키로 승격

`/ingest <파일명>` 으로 호출된다. 인자(`<파일명>`)는 `raw/` 아래의 파일을 가리킨다.
`.md` 확장자나 `raw/` 접두어는 있어도 없어도 된다 — `2026-07-26`, `2026-07-26.md`, `raw/2026-07-26.md` 모두 `raw/2026-07-26.md`로 해석한다.

인자가 비어 있으면 `raw/`에서 `ingested: false`인 파일을 찾아 관리자에게 어느 것을 인제스트할지 물어본다.

전체 스키마·페이지 양식의 근거는 볼트 루트의 **CLAUDE.md**다. 충돌 시 CLAUDE.md를 우선한다.

## 절차

1. **raw 파일을 읽는다.** 프론트매터의 `ingested`가 이미 `true`면 관리자에게 재인제스트 여부를 확인한다. 본문의 `## vocabulary` / `## expression` 섹션을 파싱한다. 각 항목은 `- 단어（요미） : 메모` 형식이고, 들여쓴 하위 `-` 항목은:
   - `source :` 또는 `출처 :` 로 시작하면 **출처**로 해석한다 (두 표기 동일 취급). 나중에 위키 페이지 프론트매터 `tags`에 포함된다.
   - 그 외에는 관리자가 직접 찾은 **예문**으로 해석한다.

2. **단어·관용어를 관리자와 짧게 논의한다 (필요 시).** 모호한 표기·뜻, 요미가나 불확실, 동음이의어 등 확인이 필요하면 묻는다. 명확하면 바로 진행한다.

3. **페이지를 만든다 (기존 항목은 스킵).** `## vocabulary` 항목 → `wiki/voca/<표제어>.md`, `## expression` 항목 → `wiki/expression/<표제어>.md`. **같은 이름의 페이지가 이미 있으면 그 항목은 스킵한다** — 덮어쓰거나 갱신하지 않고 스킵 목록에 담아 마지막(마무리)에 보고한다. 스킵된 항목은 이후 단계(4~7, MOC/링크 갱신)도 수행하지 않는다.

4. **양식을 따른다.** 단어는 `templates/voca.md`, 관용어는 `templates/expression.md`의 프론트매터·본문 구조를 따른다. 한자에 약한 관리자를 위해 **요미가나·한국 한자 대응(훈·음)** 을 빠짐없이 채운다. 확실하지 않은 요미가나·뜻은 추측하지 말고 "미상"으로 두거나 확인한다. **프론트매터 `tags`: 주제 태그는 필수(예: `[의류]`). raw에 출처가 있으면 주제와 함께 tags에 포함한다(예: `[의류, 요루시카]`). 없으면 주제만 기재한다.** **프론트매터 `last_seen`: 승격 시엔 항상 공백으로 둔다. `복습횟수`: 승격 시엔 항상 `0`으로 둔다 (둘 다 복습 시 갱신되는 필드이므로 인제스트에서는 채우지 않는다).** **페이지 맨 끝(가장 하단)의 `meta-bind-button` 복습완료 버튼 블록(+ `VIEW[{last_seen}]`)은 템플릿에 있는 그대로 유지한다 — 제거하거나 변형하지 않는다.**

5. **관리자 예문은 필수 포함.** (신규 생성하는 항목에 한함) raw에 관리자가 직접 넣은 예문(들여쓴 항목)이 있으면 그 예문을 위키 페이지 예문의 **첫 번째**로 넣고, 나머지는 LLM이 채워 총 3개를 맞춘다. 관리자 예문은 절대 임의로 수정하지 않는다.

   **LLM이 채우는 예문의 난이도.** 교과서식으로 지나치게 짧고 평이한 문장(예: 「ペンを使う。」「道を歩く。」)은 피하고, **뉴스·기사에서 쓰일 법한 문어체 수준**으로 작성한다 — 배경 상황이나 구체적 정보(수치·기관명·시점 등)가 담긴 한 문장, 종속절·수식어가 붙어 정보 밀도가 있는 문장을 지향한다. 어휘·문형은 **JLPT N2 수준까지 허용**한다 — 표제어 자체의 등급(예: N4·N5)보다 예문 전체 난이도가 높아져도 무방하다. 단, 표제어보다 어려운 단어가 섞이면 문장 안에 괄호로 풀지 않고, `## 예문` 바로 아래 `## 포함 단어 풀이` 섹션에 `단어（요미） — 뜻 (JLPT 레벨)` 형태로 모아 풀이한다 (어려운 단어가 없으면 이 섹션은 생략).
   예) 「彼はペンを使う。」(×, 너무 평이) → 「会議では出席者の多くが電子端末ではなく紙とペンを使う。」(○, 뉴스체)

6. **(단어) 링크 갱신.**
   - **상위개념**: 반드시 **링크**(일본어 개념명, 예: `[[衣服]]`)로 건다 — 태그로 만들지 않는다. 대상 페이지가 없으면 빈 링크로 두어 생성 후보로 남긴다.
   - **동의어/반의어/관련어**: **이미 wiki에 존재하는 페이지에만** `[[링크]]`를 건다. 없는 단어는 링크하지 않고 `—`로 둔다 (빈 링크 금지). 링크를 걸 때는 상대 페이지의 관련어 항목도 함께 갱신해 양방향 연결을 유지한다.

7. **(단어) 주제·MOC 갱신.** 주제는 페이지의 `## 주제`에 **태그**(`#주제`)로 달고(링크 아님), 동시에 `MOC/주제별/<주제>.md`에 해당 단어 `[[링크]]`를 추가한다 (태그+MOC 이중 표현 유지). 품사도 `MOC/품사별/<품사>.md`에 `[[링크]]`로 추가한다. MOC 파일이 없으면 새로 만든다.

8. **index.md 갱신.** 새/갱신 페이지를 해당 카테고리(단어/관용어/MOC)에 `[[링크]] — 한 줄 요약` 형식으로 등록한다. `_아직 없음_` 플레이스홀더는 첫 항목 추가 시 제거한다.

9. **log.md 갱신.** append-only로 항목을 추가한다. 형식:
   ```
   ## [YYYY-MM-DD] ingest | <raw 파일명>
   - voca: [[단어1]], [[단어2]] ...
   - expression: [[관용어1]] ...
   ```
   날짜는 오늘 날짜를 쓴다.

10. **raw 파일의 `ingested: true`로 변경한다.** 본문(학습 내용)은 절대 수정하지 않고 프론트매터 플래그만 바꾼다.

11. **상위개념 페이지 점검·생성.** 이번 인제스트로 승격된 단어들의 `## 상위개념` 링크를 모두 점검한다. 대상 상위개념 페이지가 **아직 wiki에 없으면, 그 페이지도 기존 단어와 동일하게 `templates/voca.md` 양식으로 생성**하고 4~9번(양식·요미가나·한국 한자·링크·주제 태그+MOC·index·log)을 동일하게 적용한다. 상위개념 페이지에는 관리자 예문·출처가 없으므로 예문은 LLM이 3개 채우고, `tags`에는 주제만 기재한다(출처 태그 불포함). **단, 새로 만든 상위개념 페이지의 `## 상위개념`은 링크(생성 후보)로만 두고 더 파고들지 않는다 — 1레벨에서 멈춰 무한 생성을 방지한다.**

## 마무리

완료 후 관리자에게 요약 보고:
- **생성된** 위키 페이지 (단어·관용어)
- **11번에서 자동 생성된 상위개념 페이지**
- 새로 만든 MOC
- 남긴 생성 후보(빈 `[[링크]]`) — 새 상위개념 페이지의 상위개념 등 1레벨 밖에 남은 것
- **스킵된 항목** — 이미 wiki에 존재해서 처리하지 않은 단어·관용어 (반드시 보고)

**상호연결·일관성 유지가 핵심**이다.
