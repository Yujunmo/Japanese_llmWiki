# Review — 일일 복습/테스트 목록 생성

`/review` 로 호출된다. 인자는 없다.

관리자의 하루 루틴:
- **오전**: `/review` 발동 → 그날 뽑힌 10개가 담긴 `train/review.md`로 복습.
- **저녁**: `train/test.md`(전일 오전에 복습했던 10개를 퀴즈로 만든 것)로 테스트.

즉 `train/review.md`는 "오늘 오전 복습 대상", `train/test.md`는 "오늘 저녁 테스트 대상(=어제 복습분)을 퀴즈로 렌더한 것"이다. 스킬을 한 번 발동하면 한 세대씩 밀린다. **`train.md` 중간 단계는 폐지됐다** — 예전엔 review.md를 train.md(링크 목록)로 이월했지만, 이제는 review.md를 곧바로 test.md 퀴즈로 렌더한다.

전체 스키마·경로의 근거는 볼트 루트의 **CLAUDE.md**다. 충돌 시 CLAUDE.md를 우선한다.

## 불변 규칙 (반드시 지킨다)

- **wiki/ 파일은 어떤 경우에도 수정하지 않는다.** `뜻`·`요미가나`·`last_seen` 등 값은 Read/Grep/awk로 **읽기만** 한다. (ingest가 raw/를 읽기만 하는 것과 같은 원칙.)
- 이 스킬이 쓰는 파일은 **`train/review.md`와 `train/test.md` 두 개뿐**이다. index·log·MOC·wiki를 갱신하지 않는다.
- `last_seen`·`복습횟수` 갱신은 이 스킬의 책임이 **아니다** — 각 페이지 하단의 Meta Bind 복습완료 버튼으로 사용자가 직접 갱신한다. (그때까지 미복습 단어는 `last_seen`이 공백이라 추출 우선순위가 높다.)

## 절차

### 1. 세대 이월 = test.md 퀴즈 렌더 (직전 review.md → test.md)

기존 `train/review.md`가 있으면 그 안의 10개 `[[표제어]]`를 읽어 **각 표제어의 `wiki/voca/<표제어>.md`를 열고** 다음을 읽는다:
- **표제어(한자)**: 파일명 = 표제어.
- **요미가나**: `## 요미가나` 섹션 값(또는 프론트매터 `aliases`).
- **뜻**: 본문 `**뜻**:` 줄. 프롬프트에는 **핵심 뜻만 간결히** 쓴다(부연 설명은 생략 가능).

이 10단어로 `train/test.md`를 아래 형식(덮어쓰기)으로 만든다. 기존 `train/review.md`가 **없으면(최초 실행)** 이 단계를 건너뛰고, 마무리 보고에 "최초 실행이라 test.md는 생성하지 않음"을 명시한다.

**문제 유형 (3종)** — 10문항에 **고르게 섞어** 배정한다(각 유형 3~4개). 각 단어에 한 유형만 배정한다.

- **① 한자→읽기+뜻**
  ```markdown
  ## N. <표제어(한자)>
  ① 요미가나와 뜻은?

  > [!success]- 정답
  > <요미가나> — <뜻>
  ```
- **② 뜻(한국어)→단어**
  ```markdown
  ## N. 「<한국어 뜻>」
  ② 일본어 단어와 요미가나는?

  > [!success]- 정답
  > <표제어> (<요미가나>)
  ```
- **③ 요미가나→한자**
  ```markdown
  ## N. <요미가나> — <뜻>
  ③ 한자로 쓰면?

  > [!success]- 정답
  > <표제어(한자)>
  ```

**배정 규칙**
- **한자 표기가 없는 가나 표제어(예: `つまづく`)에는 ③(요미가나→한자)을 배정하지 않는다.** ① 또는 ②로 낸다.
- **문제문(## 줄과 질문 줄)에는 `[[링크]]`를 넣지 않는다** — 링크 텍스트가 정답 한자를 노출하기 때문. 링크가 필요하면 `> [!success]` 정답 칸 안에서만 쓴다.
- 관리자는 한자에 약하므로 ①·③(한자 읽기·쓰기)에 비중을 살짝 둬도 좋다.

**test.md 전체 형식**
```markdown
# 저녁 테스트 — YYYY-MM-DD

직전 세대(어제 오전 복습)의 10단어 테스트. 각 문제를 답한 뒤 **정답 칸을 펼쳐** 채점한다.
유형: ① 한자→읽기+뜻 · ② 뜻→단어 · ③ 요미가나→한자

---

## 1. ...
...

---

## 2. ...
...

---
(… 10문항, 각 문항 사이에 `---`)

---

**점수**: ___ / 10
```
날짜는 오늘 날짜.

### 2. 새 10개 추출

`wiki/voca/*.md`의 각 파일에서 `last_seen` 값을 읽어 아래 알고리즘으로 10개(전체가 10개 미만이면 있는 만큼)를 뽑는다.

**추출 알고리즘 (오래된 풀에서 랜덤 샘플)**
1. 각 파일의 `last_seen`을 파싱한다. **값이 공백이면 정렬 키를 `0000-00-00`으로 취급**한다(= 가장 오래됨, 최우선).
2. 정렬 키 오름차순으로 정렬한다 → 가장 밀린 단어가 위로 온다.
3. 상위 **풀**(pool = min(20, 전체 개수))을 후보로 자른다.
4. 그 풀을 랜덤으로 섞어 **10개**를 뽑는다.

아래 한 줄 파이프라인으로 처리한다(macOS BSD `sort` 기준, 볼트 루트에서 실행):
```bash
for f in wiki/voca/*.md; do
  v=$(awk -F': *' '/^last_seen:/{print $2; exit}' "$f")
  printf '%s\t%s\n' "${v:-0000-00-00}" "$(basename "$f" .md)"
done | sort | head -n 20 | sort -R | head -n 10 | cut -f2
```
- `${v:-0000-00-00}` : 공백을 최우선 정렬 키로 치환.
- 첫 `sort` : 정렬 키 오름차순(오래된 순). `head -20` : 후보 풀.
- `sort -R | head -10` : 풀에서 랜덤 10개. `cut -f2` : 표제어만 남김.

### 3. review.md 갱신

추출된 표제어로 `train/review.md`를 아래 형식으로 새로 쓴다(덮어쓰기). 날짜는 오늘 날짜. 각 표제어는 `wiki/voca/<표제어>.md`를 가리키는 `[[표제어]]` 링크로만 나열한다(MOC 스타일, 뜻·예문은 넣지 않는다 — 각자 페이지에서 확인).

```markdown
# 복습 — YYYY-MM-DD

오늘의 복습 단어. 각 링크에서 뜻·요미가나·예문을 확인.

- [[표제어1]]
- [[표제어2]]
...
```

## 마무리

완료 후 관리자에게 요약 보고:
- 렌더된 `train/test.md`의 문항 수와 각 문항 유형 배분 (또는 "최초 실행 — test.md 미생성")
- 새로 추출된 `train/review.md`의 단어 10개 목록
- (참고) 현재 voca 총 개수가 10개 미만이면 추출된 실제 개수

**wiki를 건드리지 않았음**을 원칙으로 유지하는 게 핵심이다.
